# AI Code Reviewer

Кросплатформний застосунок для автоматичного рев'ю коду за допомогою AI-агента: REST API та React-клієнт (PWA для ПК і телефона).
Підтримувані мови: **Python, JavaScript, TypeScript** (повний аналіз зі статичним лінтером).
Інші мови приймаються в режимі `other`: лише AI-аналіз, без лінтера.

## Можливості

- **Рев'ю коду**: вставте код або посилання на публічний файл GitHub, отримайте оцінку та коментарі за категоріями (баги, безпека, стиль, продуктивність) з рівнем серйозності, порадою та посиланням на джерело (PEP 8, OWASP).
- **Питання до AI по коментарю**: можна уточнити, чому це погано, або попросити виправлений варіант. Кожне питання й відповідь зберігаються в історії коментаря, а наступні питання враховують попередні.
- **Чат з AI про код**: необмежена кількість чатів із постійною історією, створення, перейменування й видалення. Окремий пункт меню «Чат».
- **Проєкти та статистика**: історія рев'ю, середня оцінка, розподіл проблем за категоріями, динаміка оцінки.
- **Відповіді AI у Markdown**: списки, код, виділення. Нова відповідь з'являється поступово, рядок за рядком.
- **Облікові записи**: реєстрація з підтвердженням email, вхід (JWT), показ пароля, «Забули пароль» зі скиданням через лист.
- **PWA**: працює в браузері й встановлюється на телефон, є світла та темна теми.

## Технології

- **FastAPI**, **Pydantic v2**, **SQLAlchemy (async)**, **Alembic**
- **PostgreSQL + pgvector**: дані та векторний пошук (RAG)
- **Celery + Redis**: асинхронна обробка рев'ю
- **Google Gemini**: генерація звіту, відповідей чату та embeddings
- **Semgrep + pyflakes**: статичний аналіз (код лише аналізується, ніколи не виконується)
- **React 18 + Vite**, vite-plugin-pwa, react-markdown: клієнт
- **Docker Compose**: оркестрація (api, worker, client, db, redis, pgadmin)

## Запуск

```bash
cp .env.example .env        # заповни GEMINI_API_KEY та SECRET_KEY
docker compose up -d --build   # міграції та наповнення RAG виконуються автоматично
```

Після запуску:
- застосунок (клієнт): http://localhost:5173
- документація API: http://localhost:8000/docs

Файл `.env` містить секрети й ніколи не потрапляє в репозиторій (у git лише `.env.example`).

### Змінні середовища

| Змінна | Опис |
|--------|------|
| `GEMINI_API_KEY` | Ключ Google Gemini (обов'язково) |
| `SECRET_KEY` | Секрет для підпису JWT (обов'язково) |
| `APP_URL` | Адреса клієнта, яка підставляється в лист для скидання пароля |
| `PASSWORD_RESET_MINUTES` | Скільки діє посилання для скидання пароля (за замовчуванням 30) |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | Пошта для листів скидання пароля (див. нижче) |
| `CORS_ORIGINS`, `MAX_CODE_CHARS`, `GEMINI_MODEL` | Додаткові налаштування |

### Листи для скидання пароля

Листи надсилаються через SMTP. Для Gmail:
1. Увімкніть у Google-акаунті двоетапну перевірку.
2. Створіть «Пароль застосунку» (16 символів).
3. Впишіть у `.env`: `SMTP_USER=ваша_пошта@gmail.com`, `SMTP_PASSWORD=пароль_застосунку`, `SMTP_FROM=ваша_пошта@gmail.com` (`SMTP_HOST=smtp.gmail.com`, `SMTP_PORT=587`).
4. Перезапустіть API: `docker compose up -d api`.

Ті самі листи використовує підтвердження email при реєстрації: акаунт стає доступним після переходу за посиланням (діє 24 години, `VERIFY_EMAIL_HOURS`).

Якщо SMTP не налаштовано, надіслати лист неможливо, тому нові акаунти активні одразу, а посилання для скидання пароля пишеться в лог: `docker compose logs api`. Це зручно для розробки.

## Клієнт

React + JavaScript (Vite), PWA. Усі запити йдуть на `/api`, який проксує nginx (у Docker) або Vite (у розробці), тому CORS не потрібен.

```bash
cd client
npm install
npm run dev      # http://localhost:5173, API очікується на localhost:8000
```

`npm run dev` також друкує в терміналі QR-код з адресою для телефона (та сама Wi-Fi мережа). Для власної адреси, наприклад HTTPS-тунелю: `npm run qr -- https://адреса`.

Встановлення PWA на телефон вимагає HTTPS (або localhost); для демо з телефона використайте тунель, наприклад cloudflared чи ngrok.

Перезавантажити документацію для RAG: `docker compose exec api python scripts/seed_docs.py --reset`

## Тести

```bash
docker compose exec api pytest -q   # у контейнері, разом із тестами правил Semgrep
pytest                              # локально: AI та GitHub підміняються заглушками, Postgres не потрібен
```

Тести правил Semgrep виконуються лише там, де встановлено `semgrep` (в Docker-образі).

## Як працює рев'ю

1. `POST /reviews/` зберігає рев'ю зі статусом `pending` і одразу повертає його id.
2. Celery-воркер запускає агента: завантаження з GitHub (лише allowlist доменів) → статичний аналіз → RAG-пошук по PEP 8/OWASP/стилю мови → Gemini повертає структурований JSON.
3. Результат валідується й зберігається; статус `done` або `failed` (з повідомленням про причину).
4. Клієнт опитує `GET /reviews/{id}`.

Посилання на GitHub підтримуються лише для публічних файлів; для приватних вставте код вручну.

Мова рев'ю: явно вказана > визначена за розширенням файлу з GitHub > мова проєкту.

## Безпека

- Паролі зберігаються як bcrypt-хеші, доступ за JWT, чужі ресурси повертають 404.
- Скидання пароля: токен зберігається лише як SHA-256 хеш, діє один раз і обмежений часом; на запит для невідомої пошти відповідь така сама, тож акаунти не можна перебирати.
- Завантаження з GitHub захищене від SSRF: лише allowlist доменів, https, обмеження розміру, без токенів.
- Код користувача лише аналізується лінтером і ніколи не виконується.
- Код у промптах огороджений тегами, щоб зменшити ризик prompt injection.
- Відповіді AI рендеряться як Markdown без сирого HTML.

## API

| Метод | URL | Опис |
|-------|-----|------|
| POST | `/auth/register` | Реєстрація (пароль від 8 символів) |
| POST | `/auth/login` | Логін, повертає JWT (403, доки email не підтверджено) |
| POST | `/auth/verify-email` | Підтвердження email за одноразовим посиланням з листа |
| POST | `/auth/resend-verification` | Надіслати лист підтвердження ще раз |
| POST | `/auth/forgot-password` | Запит листа з посиланням для скидання пароля |
| POST | `/auth/reset-password` | Встановлення нового пароля за токеном з листа |
| GET | `/users/me` | Профіль |
| POST / GET | `/projects/` | Створити проєкт / список |
| GET / PATCH / DELETE | `/projects/{id}` | Перегляд / зміна / видалення |
| GET | `/projects/{id}/reviews` | Історія рев'ю проєкту |
| GET | `/projects/{id}/stats` | Середня оцінка, категорії проблем, динаміка оцінки |
| POST | `/reviews/` | Надіслати код або GitHub-посилання (202) |
| GET | `/reviews/{id}` | Статус, оцінка, коментарі, збережені питання й відповіді |
| POST | `/reviews/{id}/ask` | Питання до AI по рев'ю або по коментарю (`comment_id`), зберігається в історії |
| POST / GET | `/chats/` | Створити чат / список чатів |
| GET / PATCH / DELETE | `/chats/{id}` | Чат з історією / перейменування / видалення |
| POST | `/chats/{id}/messages` | Надіслати повідомлення й отримати відповідь AI |

## Структура

```
app/
├── api/routes/     # Роутери (auth, users, projects, reviews, chats)
├── core/           # Конфігурація, безпека (JWT), підтримувані мови
├── models/         # ORM-моделі
├── schemas/        # Pydantic-схеми
├── services/       # Бізнес-логіка (рев'ю, чат, пошта, скидання пароля)
├── agent/          # AI-агент
│   ├── tools/      # linter, github_fetcher, rag_search
│   └── rules/      # Правила Semgrep (python, javascript)
└── tasks.py        # Celery-задачі
alembic/versions/   # Міграції
scripts/seed_docs.py # Наповнення RAG
tests/              # Автотести (pytest)
client/             # React-клієнт (Vite, PWA)
mockups/            # HTML-макет інтерфейсу
```
